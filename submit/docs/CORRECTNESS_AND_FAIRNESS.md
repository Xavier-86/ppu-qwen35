# 正确性与公平性声明

本声明针对主办方发布的《DNDX 多模态推理调优赛选手说明》的要求逐条出具，覆盖接口契约、允许优化方向与禁止条例三部分。各优化点的实现细节与性能数据见 `TECHNICAL_REPORT.md`。

本声明基于本项目组成员对赛事说明与相关通知的共同理解撰写，所有优化均在项目组成员理解的规则允许范围内进行。如有任何疑问或质疑，请联系项目负责人（联系方式随提交单独提供）。

## 一、接口契约（赛事说明第 3 节）

- 选手实现为 `evaluation_wrapper.py` 及随提交的引擎源码闭包（`rapid_reasoning/`），完整保留 `VLMModel.generate_with_metrics` 的接口签名与 `GenerationResult(text, token_count, ttft_seconds, elapsed_seconds, meta)` 返回结构，接口契约无改动。
- 公开自测入口 `benchmark_public.py` 相对初始版本有少量本地自测用改动，均不触及评测口径：`--backend` 默认值改为 `sglang` 并新增该选项；新增 `--develop` 进度条显示（tqdm 为可选依赖，缺失时回退为无进度条）；答案解析正则兼容选项字母外层的 markdown 强调/代码标记（如 `**A**`）。样本加载顺序、生成参数（`max_new_tokens=256, temperature=0.0`）、指标统计与准确率计算逻辑与初始版本完全一致。主办方内部评测脚本不在本提交范围内，未做任何改动。

本提交的全部优化均落在赛事说明列出的允许方向内：

## 三、禁止条例逐条合规说明（赛事说明第 5 节）

1. **更换/蒸馏/量化权重**：未发生。使用主办方指定的 `Qwen3.5-2B` 权重，BF16 原样加载，未量化、未蒸馏、未更换；投机解码使用的 MTP 草稿头为该 checkpoint 自带（`mtp_num_hidden_layers=1`），未引入任何外部权重。
2. **修改评测数据或依赖外部私有数据**：未发生。评测数据只读使用，全部优化与验证仅基于主办方发放的公开自测集。
3. **修改主办方评测脚本、评分逻辑或反作弊逻辑**：未发生。主办方内部评测脚本不在本提交范围内；本地公开自测入口的改动见本声明第一节，不触及评分逻辑，wrapper 仅在接口契约内工作。
4. **跳过、筛选样本或提前终止**：未发生。所有请求全量逐题顺序处理，无任何样本级跳过或提前终止逻辑。
5. **按 sample_id、题号、图片 hash、题干 hash 查表**：未发生。引擎与 wrapper 中不存在任何基于样本身份或内容哈希的答案查表；输出有效性兜底（报告 2.13 节）明确不按题号、语言、数据集路径或内容 hash 特判，对所有输出统一适用同一正则校验规则。自适应链深控制器（报告 2.21 节）同样不含任何语言、题号、数据集路径或内容检测：中英文使用同一套默认配置，逐轮深度决策仅依据当前运行中实测的投机接受率与耗时信号。
6. **硬编码公开集或疑似测试集答案**：未发生。提交中不包含任何预计算答案表。
7. **联网调用外部模型、API、搜索或远程推理服务**：未发生。推理全程本地完成，不联网、不调用任何外部服务。
8. **伪造 `token_count`、`ttft_seconds`、`elapsed_seconds`**：未发生。三项指标均为引擎真实返回；wrapper 采用与公开参考实现一致的严格单次生成计量：TTFT 以首个非空解码文本 chunk 到达 wrapper 为准，elapsed 覆盖完整流式生成；如触发输出有效性兜底，首次生成与补答的 token_count、TTFT、墙钟时间合并计量，总 token_count 不超过公开校验器允许的上限。
9. **准确率与性能拆成两套策略**：未发生。准确率与性能为同一进程、同一策略、同一次运行测得。
10. **输出无法映射到唯一 A/B/C/D**：所有输出经与公开评测器一致的三组正则检查，均能映射到唯一选项；公开集全量 public validation 双语通过（报告 1.1、2.13 节）。
11. **利用解析漏洞、异常输出或超长输出影响评分**：未发生。展示文本统一限制为 1200 字符，输出格式遵守评测器解析规则。
12. **写入持久化缓存跨次复测获利**：未发生。无跨请求、跨次运行的持久化缓存；所有 CUDA Graph 均在引擎启动时于内存中重新捕获，每次运行完整重建。自适应链深控制器的接受率统计仅保存在引擎进程内存中，随进程退出销毁，每次运行从零初始化，不构成跨次运行的信息携带。

## 四、正确性验证方法

每版优化转正前均通过以下验证（详见报告第二章各小节与第五章）：

- 公开集逐题比对 `question_id / parsed_answer / correct / token_count / validation_errors` 五字段签名，要求与基线零差异；
- 图捕获路径与 eager 路径的逐位比对（greedy logits 与 Mamba 状态逐位相同）；
- 手写融合 kernel 的 `torch.equal` 逐比特单元测试，按 eager 数值语义复现 BF16 舍入；
- 链深类改动（报告 2.12、2.21 节）因改变 GDN chunk 分段存在 BF16 near-tie 合法分叉（EAGLE 类投机解码固有），此类改动的验收口径为正确题数持平、public validation 不新增失败，并以运行时接受率统计（`SGLANG_CHAIN2_STATS=1`）与逐深度钉死实验（`SGLANG_MTP_FORCE_EXTRA`）交叉核对；当前默认配置下 EN 3222、CN 3385 与历史最佳正确数完全一致，双语 public validation 全部通过；
- 少数由 BF16 near-tie 舍入翻转引起的合法 token 流分叉，均保证正确题数不变，并在报告中如实标注。

## 五、复测配合

本提交不依赖任何环境外的同名 Python 包，`runtime_manifest.json` 固定了代码闭包的来源、版本与哈希，`submission_check.py` 可在评测前自检完整性与模块来源。本地自测成绩仅供调试，最终成绩以主办方在统一环境与私有测试集上的复测结果为准。
